# درسنامهٔ پرامپت DeepWiki در Devin AI

## در یک جمله

این پرامپت سیستمی Devin (محصول Cognition) برای موقعیت «پرسش و پاسخ دربارهٔ کدبیس» یا DeepWiki است. یک Agent کدنویس را به دستیار پرسش و پاسخ پژوهشی‌ای محدود می‌کند که «فقط به پرسش‌های مربوط به همین کدبیس جواب می‌دهد». قیدهای اصلی‌اش ارجاع اجباری (citation)، ممنوعیت حدس زدن و بستن سخت مرز توانایی است.

## چرا ارزش یادگرفتن دارد

- نشان می‌دهد چطور می‌شود با پرامپت یک Agent کدنویس عمومی را به دستیار پرسش و پاسخ تخصصی «کوچک کرد»؛ بدون مدل تازه، فقط با بریدن وظیفه‌ها و قیدهای سخت.
- «اعتمادپذیری» را شهروند درجهٔ اول کرده است: هر جمله باید ارجاع `<cite>` داشته باشد. این راهی مهندسی برای مقابله با توهم و ساختن پاسخ قابل‌حسابرسی است.
- شیوهٔ نوشتن «اعلام مرز توانایی» را روشن نشان می‌دهد: صریحاً می‌گوید چه کارهایی از دستش برنمی‌آید (دیدن PR، دانستن پیاده‌سازی خود Devin) و پاسخ استاندارد برای بیرون رفتن از مرز را تعیین می‌کند.
- بخش قواعد ارجاع نمونه‌ای بسیار مشخص از «قرارداد خروجی» است و می‌شود آن را مستقیم به‌عنوان قالبی برای محدود کردن خروجی ساختارمند LLM بررسی کرد.

## ساختار پرامپت، بخش به بخش

### ۱. تعریف هویت (BACKGROUND و How Devin works)

نقش را «Devin، مهندس نرم‌افزار باتجربه» تعیین می‌کند و فوراً شیوهٔ کار را می‌گوید: کد مرتبط را در کدبیس پیدا می‌کند، در context همان کد جواب می‌دهد، به پیوند بیرونی دسترسی ندارد، تاریخچهٔ git را می‌بیند و پرسش تکمیلی را پشتیبانی می‌کند. هویت و سازوکار کار با هم داده می‌شوند تا مدل انتظار دقیقی از شکل ورودی و خروجی خودش داشته باشد.

### ۲. مرز امنیتی و مقابله با توهم (INSTRUCTIONS و IMPORTANT NOTE)

مرکز ثقل کل متن همین است. چند قید سخت روی هم آمده‌اند: دربارهٔ context کدبیس حدس نزن، اگر نمی‌دانی بگو نمی‌دانم، هرگز جواب از خودت نساز، به جای توصیف مبهم به زبان طبیعی ارجاع دقیق `code` بده، و به همان زبان کاربر جواب بده. بخش IMPORTANT NOTE خط قرمز توانایی را دقیق‌تر می‌کشد (نمی‌تواند PRهای GitHub را ببیند، تاریخچهٔ git اضافه ندارد، از خود Devin خبر ندارد) و می‌گوید در برابر پرسش بیرون از مرز فقط باید کوتاه توضیح دهد که «در توانایی فعلی‌ام نیست».

### ۳. قرارداد ابزار و خروجی (Code Citation Instructions)

با هفت قاعده کاربرد دقیق برچسب `<cite repo path start end />` را تعریف می‌کند: بعد از هر جمله ارجاع بیاید، حتی وقتی محتوایی نیست برچسب خالی بیاید، حداکثر ۵ خط، کل تابع ارجاع داده نشود، کمترین تعداد خط، و تکیه بر شمارهٔ خط‌هایی که در context آمده. نمونه‌ای از تثبیت «قابل‌راستی‌آزمایی بودن» در قالبی است که ماشین بتواند بررسی‌اش کند.

### ۴. سبک خروجی (OUTPUT FORMAT و ANSWER INSTRUCTIONS)

اسکلت ثابت Answer + Notes را تعیین می‌کند، سطح تیترها (## و ###)، کاربرد فهرست، طول بند و قواعد نمودار mermaid (بدون رنگ، برچسب داخل گیومهٔ دوتایی) را محدود می‌کند و بارها بر نهایت کوتاهی تأکید می‌کند.

## الگوهای قابل‌استفادهٔ دوباره

- **فهرست سفید مرز توانایی + پاسخ استاندارد برای بیرون از مرز**: اول مثبت اعلام کنید «فقط X از من برمی‌آید»، بعد فهرست کنید «Y و Z از من برنمی‌آید»، و در آخر جملهٔ ثابتی برای بیرون از مرز بدهید. برای هر Agent تخصصی که باید سخت محدود شود مناسب است.
- **قرارداد ارجاع اجباری**: بخواهید «هر جمله با ارجاع تمام شود و حتی وقتی لازم نیست، برچسب خالی بیاید»؛ با قاعدهٔ سخت ساختاری خروجی قابل‌حسابرسی بیرون بکشید. به حوزه‌های نیازمند اعتماد بالا مثل حقوق، پزشکی و پرسش و پاسخ پایگاه دانش منتقل می‌شود.
- **اسکلت ثابت خروجی**: دو بخش `Answer` و `Notes` که «جواب اصلی» را از «هشدار و رفع ابهام» جدا می‌کند و نویز جواب اصلی را کم می‌کند.
- **قاعدهٔ آینهٔ زبان**: «به هر زبانی که کاربر پرسید، به همان زبان جواب بده»؛ یک جمله که سازگاری چندزبانه را حل می‌کند.
- **قید قواعد نمودار**: mermaid بدون رنگ و برچسب اجباری داخل گیومهٔ دوتایی، جلوی خطای نمایش و نحو را می‌گیرد؛ شیوهٔ نوشتن پیش‌گیرانه برای یک خط لولهٔ نمایش مشخص.

## چه چیزهایی را نباید عیناً کپی کرد

- سازوکار برچسب `<cite>` به‌شدت به تزریق context کدبیس و رابط نمایش Devin وابسته است (که شمارهٔ خط می‌دهد و برچسب cite را تجزیه می‌کند). بیرون از آن خط لوله، کپی کردنش فقط انبوهی برچسب بی‌اثر می‌سازد.
- تاریخ ثابت `2025-11-09` نشانهٔ عکس لحظه‌ای است؛ در استفادهٔ دوباره باید هنگام اجرا پویا تزریق شود.
- «ارجاع اجباری برای هر جمله» در گفت‌وگوی عمومی که متنی برای ارجاع ندارد نویز می‌شود و حتی ممکن است مدل را به ساختن ارجاع جعلی بکشاند؛ فقط با context واقعی معنی دارد.
- برچسب `<budget:token_budget>200000</budget:token_budget>` نشانهٔ بودجهٔ داخلی سکوست و برای سیستمی که خودتان می‌سازید معنایی ندارد.
- بین چند قید کشمکش هست (هم هر جمله ارجاع داشته باشد، هم نهایت کوتاهی رعایت شود) که باید در موقعیت خودتان دوباره متعادلش کنید.

## موضوع‌هایی برای درس‌های بعدی

- نوشتن مرز توانایی برای Agent: روش طراحی اعلام فهرست سفید و جملهٔ استاندارد بیرون از مرز.
- مهندسی پرامپت ضدتوهم: ترکیب سه‌گانهٔ حدس نزدن، «اگر نمی‌دانی بگو» و ارجاع اجباری.
- مهندسی قرارداد خروجی: تبدیل قابل‌راستی‌آزمایی بودن به قالب برچسبی که برنامه بتواند بررسی کند.
- برش چند شکل از یک Agent پایه: مقایسهٔ پرامپت عمومی Devin با همین پرامپت DeepWiki برای توضیح محدود کردن وظیفه.
- قیدهای پیش‌گیرانهٔ قالب برای خط لولهٔ نمایش: ملاحظات مهندسی پشت جزئیاتی مثل mermaid بدون رنگ و گیومهٔ دوتایی.
