# درسنامهٔ پرامپت Agent در Cursor 2.0

## در یک جمله

این پرامپت سیستمی کامل Agent کدنویسی داخلی ویرایشگر Cursor (نسخهٔ «2.0» که گفته شده با GPT-4.1 کار می‌کند) است. هسته‌اش این است که با مجموعه‌ای از امضاهای ابزار به سبک TypeScript و انبوهی از قیدهای رفتاری، یک مدل بزرگ عمومی را به Agent کدنویسی‌ای تبدیل کند که «در IDE برنامه‌نویسی جفتی می‌کند و خودکار تا حل کامل کار جلو می‌رود».

## چرا ارزش یادگرفتن دارد

- **توضیح ابزار همان مستندات است**: توضیح ابزارها را جدا نکرده و مستقیم با اعلان TS به شکل `namespace functions { type tool = (_: {...}) => any; }` معنای ابزار را منتقل می‌کند و کامنت‌ها پر از «کی استفاده کن، کی نکن، مثال درست و غلط» است. این شیوهٔ پخته‌ای برای یکی کردن قرارداد ابزار و راهنمای استفاده است.
- **مرز تصمیم بسیار ریز نوشته شده**: مثلاً برای انتخاب بین `codebase_search`، `grep`، `read_file` و `file_search`، با چهار بند «کی استفاده نکن» و چند `<example><reasoning>`، مسئلهٔ انتخاب ابزار را از پیش حل می‌کند و به قضاوت لحظه‌ای مدل امید نمی‌بندد.
- **قیدهای خاص موقعیت IDE**: در مقایسه با Agent خط فرمان، توانایی‌های خاص IDE را نشان می‌دهد: مکان‌نما، فایل‌های باز و تاریخچهٔ ویرایش به‌عنوان context ضمنی، سپردن `edit_file` به «مدلی ضعیف‌تر» برای اعمال سریع، تشخیص با `read_lints`، ویرایش سلول نوت‌بوک، و قواعد نمایش ارجاع کد در رابط کاربری.
- **قواعد قالب ارجاع به کد** نمونهٔ کمیاب «پروتکل خروجی در خدمت رابط کاربری فرانت‌اند» است: نحو `startLine:endLine:filepath` با انبوهی مقایسهٔ good و bad؛ در اصل خروجی مدل را محدود می‌کند تا با کامپوننت نمایش نرم‌افزار میزبان جور شود.

## ساختار پرامپت، بخش به بخش

### ۱. تعریف هویت

بخش اصلی هویت فقط در انتهای متن می‌آید: `You are an AI coding assistant, powered by GPT-4.1. You operate in Cursor.`، و بر «برنامه‌نویسی جفتی» و «تو یک Agent هستی؛ تا حل کامل پرسش ادامه بده» تأکید می‌کند. تعریف مدل به‌عنوان Agentی **مستقل که نوبت را راحت پس نمی‌دهد** لحن کلیدی نسخهٔ ۲.۰ است.

### ۲. قرارداد فراخوانی ابزار (functions و multi_tool_use)

بیشترین حجم متن را می‌گیرد. هر ابزار یک اعلان نوع TS با کامنت‌های مفصل است. نکته‌های برجسته:

- ابزارها بر اساس کاربرد خوشه‌بندی شده و با هم مقایسه شده‌اند (جست‌وجو، ویرایش، ترمینال، حافظه، تشخیص، مدیریت کار).
- تابع `multi_tool_use.parallel` صریحاً فراخوانی موازی را تشویق می‌کند، حتی اگر پرامپت ترتیب را القا کند؛ طراحی‌ای با جهت‌گیری کارایی و هزینه.

### ۳. مرز امنیت و همکاری (tool_calling و making_code_changes)

- هرگز ابزاری را که داده نشده فراخوانی نکن، هرگز در گفت‌وگو نام ابزار را نیاور، و اگر مطمئن نیستی فایل را بخوان و حدس نزن.
- ابزار `run_terminal_cmd` می‌خواهد برای دستورهای تعاملی پرچم غیرتعاملی داده شود و کار طولانی در پس‌زمینه اجرا شود.
- ابزار `edit_file` تأکید می‌کند «مدل ضعیف‌تری آن را اعمال می‌کند»، پس باید با `// ... existing code ...` بخش تغییرنکرده را نشان داد، وگرنه ممکن است چیزی اشتباهی حذف شود. این قرارداد امنیتی خط لولهٔ همکاری چند مدل است.

### ۴. روش کاوش (maximize_context_understanding)

«جست‌وجوی معنایی» را ابزار اصلی کاوش تعیین می‌کند و می‌خواهد گسترده شروع شود، زیرپرس‌وجو ساخته شود، با عبارت‌های مختلف چند بار جست‌وجو شود، و گرایش به خودیاری باشد تا کمک خواستن از کاربر.

### ۵. مدیریت کار (todo_write و task_management)

با انبوهی مثال درست و غلط مرز «کی فهرست کار بسازیم» را تعیین می‌کند (۳ قدم یا بیشتر، چند کار، بازسازی) و صریحاً می‌گوید «هرگز lint، تست یا جست‌وجوی کدبیس را در فهرست کار نیاور» تا فهرست کار با جزئیات عملیاتی آلوده نشود.

### ۶. سبک خروجی (communication و citing_code)

پروتکل نمایش بلوک کد که برای رابط میزبان تنظیم شده است؛ دو قالب «نقل کد موجود» و «پیشنهاد کد تازه» را جدا می‌کند و قاطی کردنشان را ممنوع می‌کند.

## الگوهای قابل‌استفادهٔ دوباره

- **امضای ابزار + قواعد کامنت درون‌خطی**: قرارداد ابزار را با اعلان نوع در زبان هدف منتقل کنید و «کی استفاده کن، کی نکن، مثال درست و غلط» را در کامنت‌ها بگذارید؛ از پراکنده کردنشان جای دیگر متمرکزتر است و مدل کمتر نادیده‌شان می‌گیرد.
- **سه‌بخشی مثال درست و غلط + reasoning**: `<example> … <reasoning>Good/BAD: …</reasoning></example>`؛ نقطه‌های تصمیم خطاخیز (انتخاب ابزار، مرز فهرست کار، قالب خروجی) را یکی‌یکی میخ‌کوب کنید.
- **جدول تصمیم ابزارهای ناسازگار**: برای ابزارهایی با کارکرد نزدیک (جست‌وجوی معنایی، grep و خواندن فایل) قاعدهٔ انتخاب را صریح بنویسید تا مدل در انتخاب سردرگم نشود.
- **پروتکل خروجی رو به رابط میزبان**: وقتی خروجی Agent را نرم‌افزار مشخصی نمایش می‌دهد، الزام نمایش را به قید سخت + انبوهی نمونهٔ بد تبدیل کنید.
- **لحن Agentِ «تا تمام شدن ادامه بده»**: روشن کنید کی می‌شود نوبت را پس داد تا کار نیمه‌کاره نماند.

## چه چیزهایی را نباید عیناً کپی کرد

- **وابستگی شدید به مجموعه ابزار Cursor**: `edit_file`، `edit_notebook`، `read_lints`، `update_memory`، نمایش ارجاع کد و… همه به توانایی میزبان Cursor وابسته‌اند و بیرون از آن محیط معنایی ندارند.
- **فرض «مدل ضعیف‌تر ویرایش را اعمال می‌کند»**: قرارداد `// ... existing code ...` در `edit_file` محصول معماری دومدلی Cursor است و راه‌حل تک‌مدلی به آن نیازی ندارد.
- **نحو ارجاع کد `startLine:endLine:filepath`**: قرارداد نمایش مخصوص رابط Cursor است؛ در محصول دیگر درست نمایش داده نمی‌شود.
- **تاریخ قطع دانش و نام مدل** (GPT-4.1، ژوئن ۲۰۲۴) اطلاعات مشخص همین عکس لحظه‌ای‌اند و نباید به‌عنوان قالب عمومی ثابت نوشته شوند.
- **متن بسیار بلند**: کامنت‌های ابزارها خیلی مفصل‌اند و هزینهٔ توکن بالایی دارند؛ پروژهٔ کوچک لازم نیست در این مقیاس بنویسد.

## موضوع‌هایی برای درس‌های بعدی

1. **درخت تصمیم انتخاب ابزار**: با انتخاب بین `codebase_search`، `grep`، `read_file` و `file_search` به‌عنوان نمونه، نشان دهید چطور با مثال درست و غلط جلوی استفادهٔ اشتباه از ابزار را بگیریم.
2. **پروتکل ویرایش در همکاری چند مدل**: سازوکار `// ... existing code ...` در `edit_file` و بده‌بستان مهندسی «مدل اصلی diff می‌سازد، مدل ضعیف اعمال می‌کند».
3. **طراحی قرارداد خروجی رو به رابط کاربری**: قالب ارجاع کد چطور در خدمت کامپوننت نمایش فرانت‌اند است.
4. **استقلال Agent و کنترل نوبت**: کی ادامه دهد و کی بایستد و از کاربر بپرسد.
5. **مرز «ضدآلودگی» فهرست کار**: چرا lint، تست و جست‌وجو نباید وارد فهرست کار شوند.
6. **فراخوانی موازی ابزار**: انگیزهٔ کارایی و هزینهٔ `multi_tool_use.parallel`.

> نکته: این درسنامه را کنار درسنامهٔ «Cursor Agent CLI» بخوانید؛ هر دو مال Cursor‌اند، اما این یکی Agent داخل IDE است (با نوت‌بوک، lint، نمایش ارجاع کد و context ضمنی ویرایش) و نسخهٔ CLI برای محیط ترمینال است. منبع این متن عکس لحظه‌ای‌ای است که در جامعهٔ کاربران پخش شده و رسمی تأیید نشده.
