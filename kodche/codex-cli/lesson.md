# درسنامهٔ پرامپت سیستمی Codex CLI

## در یک جمله

این پرامپت سیستمی یک Agent کدنویسی ترمینال است که برای «کد مستقرشده و قابل‌اجرا» نوشته شده. هسته‌اش این است که «تغییر خودکار کد در sandbox و تحویل آن» را به سه بخش روشن تقسیم می‌کند: اعلام توانایی‌ها، قواعد کدنویسی و روند خودارزیابی پایانی.

## چرا ارزش یادگرفتن دارد

بزرگ‌ترین فرقش با دستیارهای گفت‌وگومحور این است که پیش‌فرضش «یک فضای کاری واقعی، قابل‌نوشتن و قابل‌اجرا بر پایهٔ git» است. پرامپت حول همین فرض، رفتار Agent را به رفتار هم‌تیمی دورکار و مسئولیت‌پذیر در یک تیم مهندسی محدود می‌کند: هم استقلال کافی می‌دهد (تا حل شدن کار جلو برو) و هم با قواعد کدنویسی و فهرست پایانی کف کیفیت را نگه می‌دارد. برای کسی که می‌خواهد Agent کدنویسِ «تحویل‌دهنده» بسازد، نمونهٔ نوعی و خوبی است.

## ساختار پرامپت، بخش به بخش

### ۱. تعریف هویت

همان ابتدا روشن می‌کند «تو داخل Codex CLI اجرا می‌شوی» و توانایی‌های اجرایی را فهرست می‌کند (دریافت فایل، فراخوانی تابع، اعمال وصله، اجرای دستور، برگرداندن تغییرات در sandbox، بازپخش telemetry). یک بند توضیحی هم اضافه کرده است: خودت را با مدل زبانی قدیمی Codex اشتباه نگیر. این «رفع ابهام پیش‌دستانه» ترفند کاربردی‌ای در پرامپت مدل‌های بزرگ است و جلوی خطای هویتی را می‌گیرد که از حافظهٔ آموزشی مدل می‌آید.

### ۲. مرز توانایی و استقلال

جملهٔ «تو یک Agent هستی؛ لطفاً تا حل کامل کار ادامه بده» روح چرخهٔ agentic است: صریحاً به مدل می‌گوید وسط کار توپ را به زمین کاربر نیندازد. کنارش جملهٔ «اگر مطمئن نیستی، فایل را با ابزار بخوان و هرگز حدس نزن» آمده که استقلال و اطمینان‌پذیری را به هم گره می‌زند تا Agent با اعتمادبه‌نفس چیزی از خودش نسازد.

### ۳. اعلام امنیت و مجوز

با فهرستی سفید از «کارهای مجاز» (کار روی مخزن اختصاصی، تحلیل آسیب‌پذیری، نشان دادن کد و جزئیات فراخوانی ابزار) احتیاط بیش از حد مدل را پیش‌دستانه برطرف می‌کند. این طراحی امنیتی معکوس است: بسیاری از مدل‌ها به‌خاطر نگرانی‌های کپی‌رایت یا امنیت درخواست‌های معقول را رد می‌کنند و پرامپت با مجوز صریح این نگرانی‌ها را از پیش برطرف می‌کند.

### ۴. قواعد کدنویسی (CODING GUIDELINES)

قابل‌استفاده‌ترین بخش کل متن همین است: رفع علت ریشه‌ای بهتر از وصلهٔ سطحی، پرهیز از پیچیدگی غیرضروری، نادیده گرفتن باگ‌های بی‌ربط، یکدست ماندن با سبک کد، کمترین تغییر، اضافه نکردن خودسرانهٔ سرآیند کپی‌رایت، و استفاده از git log و git blame برای context بیشتر. هر کدام از درخواست‌های پرتکرار مهندسان ارشد در بازبینی کد است که صریحاً به قاعدهٔ رفتاری Agent تبدیل شده.

### ۵. روند خودارزیابی پایانی

فهرستی که بعد از کدنویسی باید اجرا شود: بررسی سلامت با git status، حذف کامنت‌های درون‌خطی‌ای که خودش اضافه کرده با کمک git diff، بررسی سرآیند کپی‌رایتی که اشتباهی اضافه شده، اجرای pre-commit، و خلاصهٔ خروجی متناسب با پیچیدگی کار. این «خودارزیابی پیش از تحویل» نمونهٔ خوبی از تبدیل عادت‌های جاافتادهٔ مهندس انسانی به پرامپت است.

### ۶. آداب خروجی و تعامل

بین دو حالت فرق می‌گذارد: «باید فایل تغییر کند» و «فقط باید به پرسش جواب داد». اولی تحویل‌محور است و خلاصهٔ تغییرات می‌خواهد؛ دومی لحن هم‌تیمی دوستانه دارد. یک جزئیات خیلی کاربردی هم دارد: فایلی را که با apply_patch تغییر داده‌ای، از کاربر نخواه «خودش ذخیره کند» و محتوای فایل بزرگ را نچسبان؛ از تعامل زائد پرهیز می‌کند.

## الگوهای قابل‌استفادهٔ دوباره

- **مجوز به شکل فهرست سفید**: به جای نوشتن «مراقب امنیت باش»، صریحاً فهرست کنید «X، Y و Z مجاز است» تا ردکردن بی‌مورد مدل برطرف شود.
- **ادامه بده + حدس نزن**: استقلال (keep going) و اطمینان‌پذیری (don't guess, use tools) را جفتی بنویسید؛ جمله‌بندی پایدار پرامپت‌های agentic است.
- **فهرست کردن قواعد کدنویسی**: معیارهای بازبینی کد (رفع ریشه‌ای، کمترین تغییر، یکدستی سبک، بی‌توجهی به باگ‌های بی‌ربط) را به شکل موارد قابل‌اجرا بنویسید؛ از «کد خوب بنویس» کلی خیلی مؤثرتر است.
- **فهرست خودارزیابی پیش از تحویل**: git status، git diff، حذف کامنت‌ها و pre-commit مستقیم به هر Agentی که در فضای کاری git کار می‌کند منتقل می‌شوند.
- **خروجی سطح‌بندی‌شده**: برای کار کوچک چند نکتهٔ کوتاه، برای کار بزرگ توصیف سطح بالا + جزئیاتی که برای بازبین مهم است؛ تا ریزدانگی خلاصه با اندازهٔ کار جور باشد.

## چه چیزهایی را نباید عیناً کپی کرد

- قالب دقیق وصلهٔ `apply_patch`، `codex --help`، telemetry و برگرداندن sandbox به‌شدت به شکل سکوی Codex CLI گره خورده‌اند و در ابزار دیگر باید عوض شوند.
- «دسترسی شبکه غیرفعال است» و «لازم نیست git commit کنی، خودکار انجام می‌شود» فرض‌های خاص زمان اجرای همین محصول‌اند و در سکوی دیگر درست نیستند.
- قاعدهٔ «تا جای ممکن همهٔ کامنت‌های درون‌خطی را حذف کن» کمی تند است و گرایش سبک کد همین محصول را نشان می‌دهد؛ لزوماً برای همهٔ تیم‌ها مناسب نیست (بعضی تیم‌ها کامنت لازم را تشویق می‌کنند).
- منطق کار با pre-commit به وجود این پیکربندی در مخزن هدف وابسته است و قاعده‌ای مشروط است.

## موضوع‌هایی برای درس‌های بعدی

- برطرف کردن ردکردن بی‌مورد مدل‌های بزرگ با «مجوز فهرست سفید».
- طراحی هماهنگ «ادامه دادن» و «چیزی از خود نساختن» در چرخهٔ agentic.
- تبدیل معیارهای بازبینی کد به قواعد کدنویسی قابل‌اجرا برای Agent.
- روش طراحی فهرست خودارزیابی پیش از تحویل.

> پیشنهاد: این درسنامه را کنار درسنامهٔ Claude Code بخوانید؛ دو Agent کدنویسی ترمینال از دو سازندهٔ برتر. Claude Code بیشتر بر مرز امنیتی و سبک پاسخ بسیار کوتاه تکیه می‌کند و Codex CLI بیشتر بر قواعد کدنویسی و خودارزیابی پیش از تحویل.
