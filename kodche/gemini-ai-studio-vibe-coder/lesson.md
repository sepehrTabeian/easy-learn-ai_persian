# درسنامهٔ پرامپت سیستمی Gemini AI Studio (Vibe Coder)

## در یک جمله

این پرامپت سیستمی پشت «vibe coding» در Google AI Studio است، یعنی ساخت برنامهٔ وب کامل و اجراشدنی با زبان طبیعی. یک مدل عمومی را به **تولیدکنندهٔ کد فرانت‌اند** تبدیل می‌کند که **فقط XML تک‌قالب می‌دهد**، قواعد React، TypeScript و Tailwind را سخت‌گیرانه رعایت می‌کند و **کتابخانهٔ کامل استفادهٔ `@google/genai`** را در خود دارد.

## چرا ارزش یادگرفتن دارد

- **نمونهٔ واقعی Agent تولید کد در سطح تولید است، نه نمایش آموزشی.** تضاد اصلی را حل می‌کند: چطور مدلی عمومی در محیطی که کسی کد را بازبینی نمی‌کند و مستقیم کامپایل و اجرا می‌شود، کدی بدهد که فوراً کار کند.
- **نشان می‌دهد با پرامپت می‌شود «عادت بد مدل» را اصلاح کرد.** داده آموزش مدل پر از API منسوخ، نحو غلط و الگوهای دام‌دار است؛ پرامپت با جفت «درست/نادرست» همین گرایش‌ها را یکی‌یکی برمی‌گرداند.
- **قید سخت محیط اجرا را صریح نوشته است** (سندباکس نمی‌تواند مسیر URL را عوض کند، کلید API از بیرون تزریق می‌شود، برای ویدیو کاربر باید کلید خودش را انتخاب کند). نمونهٔ کلاسیک «پرامپت = قرارداد زمان اجرا».
- **بخش SDK در اصل یک راهنمای مرجع سریع API برای مدل است** (knowledge injection). نشان می‌دهد چطور «تنها شیوهٔ درست» را در زمینه قفل کنیم تا توهم کم شود.

## ساختار پرامپت، بخش به بخش

کل پرامپت دو بلوک بزرگ دارد: **نیمهٔ اول قواعد مهندسی** (چطور برنامهٔ React بنویسیم) و **نیمهٔ دوم کتابخانهٔ استفادهٔ `@google/genai`** (چطور Gemini را صدا بزنیم).

### ۱. تعریف هویت

شروع با یک جمله نقش را می‌بندد: «مهندس ارشد فرانت‌اند React در سطح جهانی با تخصص Gemini API و UI/UX» و فوراً هدف اصلی را می‌دهد: تولید برنامهٔ React کامل، اجراشدنی و زیبا.

- **چه مشکلی را حل می‌کند:** سبک خروجی را از «توضیح و آموزش» به «تحویل مستقیم محصول مهندسی» می‌برد.
- **نکتهٔ خوب:** هویت، پشتهٔ فناوری و خواست زیبایی‌شناسی در یکی آمده است و پایان پرامپت دوباره با حروف بزرگ (`AESTHETICS ARE VERY IMPORTANT`) تأکید می‌کند؛ یعنی «لنگر احساسی» در ابتدا و انتها.
- **الگوی قابل‌استفادهٔ دوباره:** نقش را به **معیار قابل‌راستی‌آزمایی خروجی** گره بزنید (کامل، اجراشدنی، زیبا)، نه جملهٔ تهی «تو متخصصی».

### ۲. قرارداد قالب خروجی (سخت‌ترین مرز)

**کل پاسخ** باید یک بلوک XML معتبر با ساختار `<changes>/<change>/<file>/<content>` باشد، محتوا داخل `<![CDATA[...]]>` بیاید و صریحاً گفته شده «فقط XML برگردان، بدون توضیح».

- **چه مشکلی را حل می‌کند:** مصرف‌کنندهٔ خروجی برنامه است نه آدم؛ هر سلام و توضیحی فرایند ذخیرهٔ خودکار فایل‌ها را می‌شکند.
- **نکتهٔ خوب:** اول قالب کامل XML را می‌دهد، بعد «قواعد XML» را اضافه می‌کند و در آخر اولین فایل را `metadata.json` تعیین می‌کند؛ یعنی **قابل‌تجزیه بودن ماشینی** قید اول است.
- **الگوی قابل‌استفادهٔ دوباره:** وقتی خروجی Agent را برنامه مصرف می‌کند، سه‌قطعهٔ «طرحوارهٔ دقیق + مثال نادرست (توضیح نیاور) + قاعدهٔ escape» را بدهید.

### ۳. قواعد مهندسی و «جفت درست/نادرست»

بخش‌های ۱ تا ۹ قواعد سخت React/TypeScript/Tailwind هستند: ساختار پوشه، قواعد import، `enum` به‌جای `const enum`، فقط Tailwind، موبایل‌اول، `createRoot`، escape رشتهٔ قالب، ویرگول بعد از جنریک در تابع پیکانی، حلقهٔ بی‌نهایت هوک، دامنهٔ کامپوننت.

- **چه مشکلی را حل می‌کند:** مدل را از خطاهایی که از نظر آماری دوست دارد مرتکب شود دور می‌کند (مثل `ReactDOM.render`، `import type` برای مقدار enum، تعریف کامپوننت فرزند داخل والد که فوکوس را می‌پراند).
- **نکتهٔ خوب:** تقریباً هر قاعده یک جفت کد **درست/نادرست** دارد و **چرا** را هم می‌گوید (مثلاً زنجیرهٔ علت‌ومعلولی حلقهٔ `useEffect` + `useCallback`). این «مقایسه + علت» از ممنوعیت خشک مؤثرتر است.
- **الگوی قابل‌استفادهٔ دوباره:** برای اصلاح یک عادت بد مشخص، نه ممنوعیت انتزاعی، بلکه **کد نادرست + کد درست + یک جمله علت** بگذارید.

### ۴. قید محیط اجرا

سندباکس را صریح می‌گوید: پیشوند `src/` ممنوع، مسیر URL قابل تغییر نیست (`BrowserRouter` ممنوع، `HashRouter` مجاز)، فایل CSS جدا نداریم و تصویر جای‌نگهدار از `picsum.photos` می‌آید.

- **چه مشکلی را حل می‌کند:** مدل نمی‌داند در سندباکس محدود اجرا می‌شود؛ باید واقعیت‌های محیط را به زمینه داد.
- **الگوی قابل‌استفادهٔ دوباره:** هر «واقعیت تغییرناپذیر وابسته به محیط» را به فهرست صریح تبدیل کنید و منتظر استنباط مدل نمانید.

### ۵. تزریق دانش SDK (کلید API، انتخاب مدل، مثال هر قابلیت)

نیمهٔ دوم کتابخانهٔ ساختاریافتهٔ استفادهٔ `@google/genai` است: راه‌اندازی، منبع کلید API، جدول نام مستعار مدل، متن، JSON، فراخوانی تابع، جریانی، تصویر، گفتار، ویدیو، Live، Chat، Grounding و مدیریت خطا؛ هر بخش با مثال `ts` قابل‌کپی و «فهرست سیاه APIهای منسوخ».

- **چه مشکلی را حل می‌کند:** SDK در حافظهٔ مدل ممکن است قدیمی باشد (`GoogleGenerativeAI`، `getGenerativeModel`) و کد تولیدشده کار نکند. پرامپت با «تنها شیوهٔ درست + فهرست ممنوع صریح» دانش کهنه را بازنویسی می‌کند.
- **نکتهٔ خوب:**
  - **جدول نام مستعار ← نام کامل** (مثلاً «nano banana» ← `gemini-2.5-flash-image`) زبان محاوره را به شناسهٔ واقعی مدل برمی‌گرداند.
  - **جدول تصمیم «نوع کار ← مدل پیش‌فرض»** انتخاب‌های دلخواه مدل را کم می‌کند.
  - بسیار از `IMPORTANT`، `CRITICAL` و `Do not` برای قیدهای کلیدی استفاده می‌کند (مثل اینکه کلید API فقط از `process.env.API_KEY` می‌آید و هرگز رابط درخواست کلید نمی‌سازی).
- **الگوی قابل‌استفادهٔ دوباره:** وقتی Agent باید SDK‌ای را که سریع تغییر می‌کند پایدار صدا بزند، مطمئن‌ترین راه این است که «تنها استفادهٔ درست فعلی» را به‌صورت بلوک دانش در پرامپت سیستمی ثابت کنید و فهرست منسوخ‌ها را کنارش بگذارید.

### ۶. مرز امنیت و کلید

بخش کلید API نمونهٔ امنیتی است: کلید **فقط** از `process.env.API_KEY` گرفته می‌شود، **هرگز** رابط ورود یا مدیریت کلید ساخته نمی‌شود و از کاربر نخواسته می‌شود کلید را در کد بنویسد. در سناریوی ویدیوی Veo عکسش است: کاربر باید با `window.aistudio.openSelectKey()` کلید خودش را انتخاب کند و پیوند صورت‌حساب هم باید نشان داده شود.

- **چه مشکلی را حل می‌کند:** منطق مدیریت کلید به کد تولیدشده نشت نمی‌کند و پلتفرم کلید را از بیرون تزریق می‌کند.
- **الگوی قابل‌استفادهٔ دوباره:** «اعتبارنامه را میزبان تزریق می‌کند و Agent خودش نباید بخواهد یا سخت‌کد کند» پیش‌فرض امنیتی ارزشمندی برای کپی کردن است.

## الگوهای قابل‌استفادهٔ دوباره

- **الگوی قرارداد خروجی:** طرحوارهٔ دقیق + «فقط X برگردان، توضیح نده» + قاعدهٔ escape/CDATA، برای خروجی‌ای که برنامه مصرف می‌کند.
- **الگوی جفت درست/نادرست:** قوی‌ترین سلاح برای اصلاح عادت بد مدل، همراه با توضیح علت.
- **الگوی تزریق دانش:** «تنها شیوهٔ درست + فهرست سیاه منسوخ‌ها» برای مهار توهم نسخه در SDK سریع‌التغییر.
- **جدول نام مستعار / جدول تصمیم پیش‌فرض:** زبان محاوره و نیاز مبهم را به پارامتر فنی قطعی تبدیل می‌کند.
- **فهرست قرارداد محیط:** واقعیت‌های تغییرناپذیر سندباکس و زمان اجرا را صریح بنویسید.
- **لنگر احساسی ابتدا و انتها:** اول هویت را بگویید، در آخر با حروف بزرگ هدف اصلی (زیبایی + کارکرد) را تکرار کنید.

## چه چیزهایی را نباید عیناً کپی کرد

- **شناسه و نسخهٔ مدل‌ها زمان‌دارند:** `gemini-2.5-flash`، `veo-3.1-*`، `imagen-4.0-*` و تاریخ‌هایی مثل `-preview-09-2025` منقضی می‌شوند و کپی کردنشان به مدلی کهنه یا ناموجود اشاره می‌کند.
- **گره خوردن به سندباکس AI Studio:** `window.aistudio.*`، خروجی XML تک‌فایلی، ممنوعیت پیشوند `src/` و قفل بودن مسیر URL قیدهای مخصوص این پلتفرم‌اند و در محیط دیگر باید بازنویسی شوند.
- **سیاست افراطی «بدون توضیح»:** فقط وقتی خروجی را برنامه تجزیه می‌کند معنا دارد؛ در Agent همکاری انسانی که باید استدلال را هم توضیح بدهد تجربه را خراب می‌کند.
- **حجم بسیار بزرگ پرامپت:** گذاشتن کل مستندات SDK در پرامپت سیستمی زمینه را زیاد اشغال می‌کند و هزینه را بالا می‌برد؛ در پروژهٔ عادی باید بر اساس نیاز برش بزنید.
- **ایرادهای کوچک منبع:** مثلاً علامت `*.` در گلوله بخش واکنش‌گرا، یا متغیرهای تعریف‌نشده در برخی مثال‌های صوتی، نشان می‌دهد این یک محصول مهندسی است، نه آموزش پرداخت‌شده؛ نیازی به تقلید ظاهرش نیست.

## موضوع‌هایی برای درس‌های بعدی

1. **طراحی قرارداد خروجی قابل‌تجزیه برای Agent تولید کد:** با مثال XML تک‌فایلی این پرامپت.
2. **اصلاح عادت بد مدل با جفت درست/نادرست:** تمرین از روی حلقهٔ هوک React، دامنهٔ کامپوننت و escape رشتهٔ قالب.
3. **تزریق دانش SDK و فهرست سیاه منسوخ‌ها:** مقابله با توهم نسخه در کتابخانه‌های سریع‌التغییر.
4. **امنیت اعتبارنامه: تزریق در برابر درخواست:** مقایسهٔ سناریوی متن (تزریق از بیرون) و سناریوی Veo (انتخاب کلید توسط کاربر).
5. **جدول نام مستعار و جدول تصمیم پیش‌فرض:** تکنیک مشخص کردن نیاز مبهم.

> نکته: تاریخ و نام مدل‌ها در این منبع عکس لحظه‌ای‌اند؛ تمرکز درس را روی «ساختار و روش» بگذارید. برای مقایسه [v0](../v0/lesson.md) و [Lovable](../lovable/lesson.md) را هم ببینید: هر سه Agent تولید برنامهٔ وب‌اند ولی هر کدام قرارداد خروجی متفاوتی دارند.
