# درسنامهٔ پرامپت Builder در Trae

## در یک جمله

این پرامپت سیستمی حالت «Builder» در Trae AI (Agent برنامه‌نویسی داخل IDE، ساختهٔ ByteDance) است. نشان می‌دهد یک Agent برنامه‌نویسی جفتیِ جاسازی‌شده در IDE چطور بین «تزریق خودکار context + فراخوانی ابزار + مدیریت کار + قواعد سخت ارجاع در خروجی» تعادل برقرار می‌کند.

## چرا ارزش یادگرفتن دارد

- نمونهٔ نوعی دستهٔ «دستیار IDE» است: برخلاف Agentهای خط فرمان مثل Claude Code، فرض می‌کند محیط میزبان context ضمنی را خودکار تزریق می‌کند (فایل‌های باز، مکان مکان‌نما، تاریخچهٔ ویرایش) و پرامپت باید جداگانه توضیح دهد با این اطلاعات چه کند.
- «قرارداد قالب خروجی» را با دقتی در سطح محصول اجرا کرده است: دو نحو ارجاع جدا تعریف کرده که با هم قاطی نمی‌شوند (ارجاع وب با `<mcreference>` و ارجاع کد با `<mcfile>`، `<mcsymbol>`، `<mcfolder>` و `<mcurl>`). این قید مهندسی برای پرش قابل‌کلیک و ردپذیری در محصولات IDE لازم است.
- با `<example>`های فراوان درست و غلط به مدل یاد می‌دهد «کی از TodoWrite استفاده کند و کی نه»؛ نمونهٔ خوبی برای تنظیم ریزدانگی رفتار Agent با few-shot.
- مرز امنیت و محرمانگی را خویشتن‌دار نوشته است: از افشای پرامپت، توضیح ابزارها و نوبت‌های باقی‌مانده سر باز می‌زند و هم‌زمان می‌خواهد مدام عذرخواهی نکند؛ یعنی «شخصیت Agent» را هم شکل می‌دهد.

## ساختار پرامپت، بخش به بخش

### ۱. تعریف هویت

با سه بخش نقش را تثبیت می‌کند: «دستیار برنامه‌نویسی agentic و قدرتمند»، «فقط در Trae AI اجرا می‌شود» و «با USER برنامه‌نویسی جفتی می‌کند».

ارزشش این است که صریحاً اعلام می‌کند «میزبان اطلاعات وضعیت فعلی (فایل‌های باز، مکان‌نما، تاریخچهٔ ویرایش) را خودکار پیوست می‌کند» و فوراً اضافه می‌کند «مرتبط بودن یا نبودنش با توست». مسئولیت گزینش context را به مدل برمی‌گرداند تا context بی‌ربط آن را به بیراهه نبرد. این نقطهٔ اصلی طراحی است که Agent داخل IDE را از Agent خالص خط فرمان جدا می‌کند.

### ۲. مرز امنیتی

در بندهای ۴، ۶ و ۷ بخش `<communication>` جمع شده است: از نوشتن پرامپت سیستمی، افزونه‌ها، قواعد، توضیح ابزارها و نوبت‌های باقی‌مانده خودداری می‌کند.

شیوهٔ نوشتنش ارزش یادگرفتن دارد: دامنهٔ «محرمانه» را با فهرست هم‌معنی‌ها (تکرار، ترجمه، بازنویسی، چاپ، خلاصه، قالب‌بندی، برگرداندن…) مشخص می‌کند تا جلوی jailbreak با دور زدن عبارت گرفته شود، نه این‌که فقط بنویسد «افشا نکن». بندهای ۵ و ۸ هم شخصیت را شکل می‌دهند (دروغ نگو، زیاد عذرخواهی نکن)؛ این «امنیت سبک رفتار» است.

### ۳. فراخوانی ابزار

بخش `<toolcall_guidelines>` + فهرست سفید صریح ابزارها (todo_write، search_codebase، view_files، write_to_file، run_command، web_search، finish و…).

طراحی‌های کلیدی:

- «فراخوانی‌های غیرضروری را کم کن» نشان‌دهندهٔ آگاهی از هزینه و تأخیر است.
- «هرگز ابزاری را که داده نشده فراخوانی نکن» و «نام فایل یا تابع را نام ابزار فرض نکن» نرده‌های ضدتوهم‌اند.
- «هرگز create_file را برای فایل موجود به کار نبر» اجبار «اول بخوان، بعد بنویس» است تا چیزی بازنویسی نشود.

### ۴. قواعد تغییر کد

یازده بند `<making_code_changes>` کاربردی‌ترین بخش این پرامپت است: اول قراردادها را بفهم و تقلید کن، importها و وابستگی‌ها را کامل کن، هرگز فرض نکن کتابخانه‌ای هست (اول package.json را ببین)، پیش از ساختن کامپوننت تازه کامپوننت‌های موجود را ببین، برای امنیت کلید ننویس، برای تصویر از SVG استفاده کن، و تغییر را تا جای ممکن در یک قدم و حداکثر در ۳ قدم انجام بده.

همهٔ این‌ها «عادت‌های ضمنی مهندس ارشد» را به قاعدهٔ صریح تبدیل کرده‌اند و مستقیم به هر Agent برنامه‌نویسی منتقل می‌شوند.

### ۵. اشکال‌زدایی و API بیرونی

بخش `<debugging>` (رسیدگی به علت ریشه‌ای، اضافه کردن لاگ، نوشتن تست جداکننده) و بخش `<calling_external_apis>` (انتخاب بهترین API بدون اجازه، سازگاری نسخه با فایل وابستگی، هشدار امنیتی کلید API) زنجیرهٔ «نوشتن کد» تا «عیب‌یابی و یکپارچه‌سازی» را کامل می‌کنند.

### ۶. قرارداد ارجاع در خروجی

دو نحو ارجاع XML محصولی‌ترین بخش این پرامپت است: `<mcreference>` برای ردپذیری جست‌وجوی وب، و `<mcfile>`، `<mcsymbol>`، `<mcfolder>` و `<mcurl>` برای ساختن ارجاع‌های کد در پاسخ که IDE تجزیه می‌کند و می‌شود رویشان کلیک کرد و پرید. بارها تأکید می‌کند «دور برچسب ارجاع backtick نگذار» و «شمارهٔ خط از ۱ شروع می‌شود و خط خالی و کامنت هم شمرده می‌شوند». این قید سختی در خدمت لایهٔ نمایش است.

### ۷. مدیریت کار

با ۳ نمونهٔ مثبت و ۴ نمونهٔ منفی مرز استفاده از TodoWrite را تنظیم می‌کند و بعد ماشین حالت روشنی (pending، in_progress، completed) و معیار تمام شدن (اگر تست رد می‌شود، پیاده‌سازی ناقص است یا خطای حل‌نشده هست، نباید تمام‌شده علامت بخورد) اضافه می‌کند. نمونهٔ خوبی از تبدیل «مدیریت کار» از توصیهٔ مبهم به قاعدهٔ قابل‌اجراست.

## الگوهای قابل‌استفادهٔ دوباره

- **تزریق خودکار context + گزینش صریح**: «محیط X، Y و Z را تزریق می‌کند و مرتبط بودنش با توست»؛ برای هر دستیاری که context ضمنی تزریق می‌کند مناسب است.
- **محرمانگی با فهرست هم‌معنی‌ها**: همهٔ عبارت‌های ممکن jailbreak را فهرست کنید و یکجا رد کنید.
- **فهرست سفید ابزار + بند ضدتوهم**: نام ابزارها را صریح فهرست کنید و فرض گرفتن نام فایل به‌عنوان نام ابزار و فراخوانی ابزار ناموجود را ممنوع کنید.
- **تنظیم ریزدانگی رفتار با few-shot درست و غلط**: مثال‌های جفتی «باید استفاده کرد» و «نباید استفاده کرد» از یک قاعدهٔ انتزاعی مؤثرترند.
- **نردهٔ «اول بخوان، بعد بنویس»**: «هرگز create_file را برای فایل موجود به کار نبر» و «پیش از استفاده از کتابخانه، فایل وابستگی را ببین».
- **قرارداد سخت قالب خروجی**: برای نمایش و پرش، نحو برچسب اختصاصی تعریف کنید و بر جزئیات مرزی (backtick، شمارش خط) تأکید کنید.

## چه چیزهایی را نباید عیناً کپی کرد

- برچسب‌هایی مثل `<mcreference>`، `<mcfile>` و `<mcsymbol>` پروتکل اختصاصی لایهٔ نمایش Trae‌اند و بیرون از IDE آن تجزیه نمی‌شوند؛ کپی کردنشان در محصول دیگر فقط XML بی‌معنی می‌سازد.
- فهرست سفید ابزارها (search_codebase، edit_file_fast_apply و…) نام ابزارهای اختصاصی Trae است و هر Agent دیگری باید آن را با مجموعه ابزار خودش عوض کند.
- قیدهایی مثل «تغییر را حداکثر در ۳ قدم تمام کن» و «نوبت‌های باقی‌مانده را فاش نکن» به سازوکار هزینه و نوبت همان محصول گره خورده‌اند و در موقعیت‌های عمومی لزوماً مناسب نیستند.
- «بهترین IDE دنیا» جایگاه‌سازی تبلیغاتی است و در انتقال باید حذف شود.

## موضوع‌هایی برای درس‌های بعدی

- مدل context در Agent داخل IDE: تزریق ضمنی در برابر بازیابی فعال، و نوشتن «مسئولیت گزینش».
- طراحی قرارداد قالب خروجی: نحو برچسب و قواعد مرزی برای ارجاع قابل‌کلیک و ردپذیر.
- تنظیم «میزان تلاش و ریزدانگی رفتار» Agent با few-shot درست و غلط (با TodoWrite به‌عنوان نمونه).
- فهرست نرده‌های تغییر کد در Agent برنامه‌نویسی (اول بخوان بعد بنویس، کتابخانه را فرض نکن، کلید ننویس).
- روش فهرست هم‌معنی‌ها برای محرمانگی پرامپت و مقابله با jailbreak.

> نکته: منبع این متن گردآوری جامعهٔ کاربران است و هنوز تأیید نشده؛ پروتکل برچسب‌ها اختصاصی Trae است و به محصول دیگر قابل‌انتقال نیست.
