# درسنامهٔ چرخهٔ Agent در Manus

## در یک جمله

این تکه بخش آغازین پرامپت سیستمی Manus است. با «هویت + فهرست توانایی‌ها + قاعدهٔ زبان کاری + توانایی‌های سیستم + چرخهٔ شش‌مرحله‌ای agent loop» اسکلت اجرای یک Agent عمومی کامپیوتری را می‌سازد. نکتهٔ اصلی‌اش این است که ریتم اجرای Agent را صریحاً به شکل یک ماشین حالت چرخه‌ای نوشته است.

## چرا ارزش یاد گرفتن دارد

- نشان می‌دهد چطور می‌شود با متنی بسیار کوتاه (حدود ۳۰ خط) روشن کرد که یک Agent عمومی «کیست، چه کاری از او برمی‌آید و قدم‌به‌قدم چطور کار می‌کند». تراکم اطلاعاتش بالاست.
- «شش مرحلهٔ agent loop» باارزش‌ترین بخش این پرامپت است: «اجرای خودکار» انتزاعی را به چرخه‌ای بسته تبدیل می‌کند: تحلیل رویداد ← انتخاب ابزار ← انتظار برای اجرا ← تکرار ← تحویل ← آماده‌باش. این مدل ذهنی برای ساختن هر Agent از نوع ReAct یا رویدادمحور قابل‌استفاده است.
- قید «در هر دور فقط یک فراخوانی ابزار» قیدی خویشتن‌دار و کلیدی است. جلوی این را می‌گیرد که Agent یک‌باره و کورکورانه اقدام‌ها را روی هم بچیند و بازخورد نتیجه‌های میانی را از دست بدهد. یعنی به مشاهده‌پذیری هر قدم اهمیت داده شده است.
- دو لایهٔ «توانایی‌ها» (capabilities) و «روند اجرا» (loop) را آشکارا از هم جدا کرده است. لایه‌بندی ساختارش روشن است و نمونهٔ خوبی برای نوشتن پرامپت است.

## ساختار پرامپت، بخش به بخش

### ۱. تعریف هویت

جملهٔ اول هویت را مشخص می‌کند (Manus، یک Agent هوش مصنوعی ساختهٔ تیم Manus) و بلافاصله فهرستی شش‌موردی از «کارهایی که در آن‌ها مهارت دارد» می‌آورد که حوزهٔ توانایی Agent را از جمع‌آوری اطلاعات، تحلیل داده و نوشتن تا ساختن وب‌سایت و برنامه‌نویسی عمومی پله‌پله باز می‌کند. این شیوه، یعنی «هویت + حوزه‌های مهارت»، هم نقش مدل را تعیین می‌کند و هم به‌طور ضمنی مرز کارها را می‌کشد.

### ۲. قاعدهٔ زبان کاری

بخش میانی فقط به رفتار زبانی می‌پردازد: پیش‌فرض انگلیسی است، اگر کاربر زبانی تعیین کرد همان زبان استفاده شود، فکر کردن و پاسخ دادن هر دو به زبان کاری باشد، آرگومان‌های زبان طبیعی در فراخوانی ابزار هم به همان زبان باشد، و به‌ویژه «از قالب فهرست خالص و نقطه‌گذاری فهرستی پرهیز شود». این قید یکدستی برای محصولات چندزبانه و بین‌منطقه‌ای خیلی کاربردی است و ترجیح سبک خروجی را هم نشان می‌دهد.

### ۳. توانایی‌های سیستم (System capabilities)

فهرستی از ابزارهای اجرایی واقعی Agent را برمی‌شمارد: ابزار پیام، sandbox لینوکس متصل به اینترنت، shell و ویرایشگر و مرورگر، برنامه‌نویسی به چند زبان، نصب خودکار وابستگی‌ها، استقرار با دسترسی عمومی، و در صورت لزوم پیشنهاد به کاربر برای در دست گرفتن مرورگر در عملیات حساس. این بخش «توانایی انتزاعی» را به «ابزار و محیط مشخص» تبدیل می‌کند تا مدل بداند چه برگ‌هایی در دست دارد. پیشنهاد این‌که «کاربر در عملیات حساس موقتاً مرورگر را در دست بگیرد» طراحی قابل‌توجهی برای همکاری امن است.

### ۴. چرخهٔ شش‌مرحله‌ای Agent Loop

بخش اصلی: اجرای کار به شکل چرخه‌ای تکرارشونده تعریف شده است: تحلیل رویدادها، انتخاب ابزار، انتظار برای اجرا، تکرار، تحویل نتیجه، ورود به آماده‌باش. ورودی جریان رویداد (event stream) است، کوچک‌ترین واحد اقدام یک فراخوانی ابزار است، انضباط اجرا تکرار صبورانه است، و در پایان نتیجه به شکل پیوست پیام تحویل داده می‌شود و Agent به حالت بیکار برمی‌گردد تا منتظر کار تازه بماند. این توصیف کامل یک ماشین حالت است.

## الگوهای قابل‌استفادهٔ دوباره

- **ساختار دولایهٔ فهرست مهارت + توانایی سیستم**: لایهٔ بالا می‌گوید «در حل چه مسئله‌هایی مهارت دارم» (رو به ارزش برای کاربر) و لایهٔ پایین می‌گوید «چه ابزار و محیط مشخصی دارم» (رو به اجرا). جدا کردن این دو، هم تعیین نقش و هم نگاشت ابزارها را روشن‌تر می‌کند.
- **قالب صریح agent loop**: «تحلیل رویداد ← انتخاب ابزار ← انتظار برای اجرا ← تکرار ← تحویل نتیجه ← آماده‌باش» را می‌شود مستقیم اسکلت اجرای هر Agent خودکاری کرد.
- **انضباط یک اقدام در هر قدم**: قید «در هر دور فقط یک فراخوانی ابزار» را می‌شود در هر Agent ابزارمحوری نوشت تا مجبور شود بعد از هر قدم نتیجه را جذب کند و بعد تصمیم بگیرد.
- **قاعدهٔ یکدستی زبان کاری**: زبان پیش‌فرض + پیروی از کاربر + یکی بودن زبان فکر، پاسخ و آرگومان ابزار؛ قالبی آماده برای پرامپت محصولات چندزبانه.

## چه چیزهایی را نباید عیناً کپی کرد

- هویت و نام تیم (Manus) مخصوص برند است و در استفادهٔ دوباره باید با محصول خودتان عوض شود.
- عبارت «sandbox لینوکس، استقرار با دسترسی عمومی، نصب خودکار وابستگی‌ها» محیط اجرای خاص Manus را توصیف می‌کند. اگر Agent شما این توانایی‌های زیربنایی را ندارد، کپی کردنشان توهم توانایی می‌سازد.
- این فقط تکهٔ آغازین پرامپت کامل است. قواعد دقیق فراخوانی ابزار، ماژول‌های برنامه‌ریزی و حافظه، بازیابی از خطا و جزئیات امنیتی را ندارد و نمی‌شود آن را پرامپت کامل و مستقلی دانست.
- «پرهیز از فهرست خالص و نقطه‌گذاری فهرستی» ترجیح سبکی Manus است و لزوماً با نیاز خروجی محصول شما جور نیست.

## موضوع‌هایی برای درس‌های بعدی

- طراحی ماشین حالت اجرایی چرخه‌ای برای Agent عمومی، با همین شش مرحله به‌عنوان نمونه و مقایسه با الگوهایی مثل ReAct و Plan-and-Execute.
- دو سطح توصیف توانایی: ارزش برای کاربر در برابر ابزار اجرایی؛ طراحی لایه‌ای هویت و نگاشت ابزارها در پرامپت.
- انضباط یک فراخوانی ابزار در هر قدم؛ چرا محدود کردن اقدام در هر دور به مشاهده‌پذیری و کنترل‌پذیری کمک می‌کند.
- یکدستی زبان کاری در Agent چندزبانه؛ موضوعی کوچک اما کاربردی در مهندسی پرامپت.
- همکاری انسان و ماشین در عملیات حساس؛ با پیشنهاد «کاربر مرورگر را در دست بگیرد» به‌عنوان شروع بحث دربارهٔ طراحی واگذاری امن.

> نکته: این متن فقط تکهٔ آغازین پرامپت است و منبعش تأیید نشده؛ پرامپت کامل Manus نیست. برای دیدن بقیهٔ قواعد، درسنامهٔ «ماژول‌های Manus» را بخوانید.
